@odpc-platform-x/nest-oidc-odpc-x-idp

Reusable NestJS OIDC (authorization-code + PKCE) module against the ODPCX IdP Link, plus a jose RS256 session cookie.

NestJS 11
TypeScript 5
OpenID Connect
jose v5/v6
Vitest
npm install @odpc-platform-x/nest-oidc-odpc-x-idp openid-client jose

Overview

Overview

แพ็กเกจนี้ทำหน้าที่เป็น auth module สำเร็จรูปสำหรับ NestJS แอปที่ต้องล็อกอินผ่าน ODPCX IdP Link ด้วย OAuth2 authorization-code flow (PKCE) แล้วออก session cookie ของตัวเองที่เซ็นด้วย RS256 (jose) แทนการอิง session ของ IdP โดยตรง ตัวแพ็กเกจเป็น generic core เท่านั้น — ไม่มี role, ไม่มี Prisma, ไม่มี JIT-provisioning logic ผูกมาด้วย — ฝั่ง host แอปต้อง implement AuthUserService หนึ่งอินเทอร์เฟซเพื่อเชื่อมกับ user store ของตัวเอง

Browser
/auth/login
ODPCX IdP Link
/auth/callback
sx_session cookie

ผู้ใช้ล็อกอินผ่าน ODPCX IdP Link แล้วได้รับ token กลับมาเป็น session cookie ที่เซ็นด้วย RS256

หลังจากนั้น ทุก request ที่ต้อง auth จะแนบ sx_session cookie มาด้วย — AuthGuard verify JWT แล้วยิง GET /auth/me → GetMeUseCase เรียก AuthUserService.getMe() (ถ้า host implement ไว้) เพื่อคืนข้อมูล user เต็มรูปแบบ

Setup

Requirements

  • Node >= 18 — required per package.json engines field
  • openid-client v6 only — v5 class-based API (Issuer, BaseClient) is incompatible; this package uses v6 functional API
  • jose v5 or v6 — peer dependency for RS256 JWT operations
  • Host app must register cookie-parser middleware before any auth routes — AuthGuard reads req.cookies, and without this middleware every request will 401: 
    import cookieParser from 'cookie-parser'
const app = await NestFactory.create(AppModule)
app.use(cookieParser())
// ... rest of setup
  • SPA on different origin? Enable CORS and fetch with credentials: 
    app.enableCors({
  origin: process.env.SPA_ORIGIN,
  credentials: true,
})

// Client-side:
fetch('/auth/login', { credentials: 'include' })

Get running

Quickstart

  1. Implement AuthUserService

    นี่คือจุดเดียวที่ host แอปต้อง implement เอง — JIT-provisioning, Prisma upsert, role logic ทั้งหมดไปอยู่ที่นี่

    import { Injectable } from '@nestjs/common'
import { AuthUserService, OidcClaims, SessionUser } from '@odpc-platform-x/nest-oidc-odpc-x-idp'

@Injectable()
class MyAuthUserService implements AuthUserService {
  constructor(private readonly users: UserRepository) {}

  async onLogin(claims: OidcClaims): Promise<SessionUser> {
    // your own Prisma upsert / JIT role provisioning / season logic goes here
    const user = await this.users.upsertByIdpSub(claims)
    return { sub: user.id, email: user.email, displayName: user.displayName, roles: user.roles }
  }

  // optional — defaults to returning the session payload as-is
  async getMe(sessionUser: SessionUser) {
    return this.users.findWithRoles(sessionUser.sub)
  }
}

  2. Wire up AuthModule.forRoot(options, provider)

    forRoot รับ สองอาร์กิวเมนต์: config object และ Nest Provider (class หรือ { provide, useFactory }) สำหรับ AuthUserService — ไม่ได้รวมกันเป็น options เดียวเพราะ provider เป็น host-implemented class ไม่ใช่ data ธรรมดา 

    import { Module } from '@nestjs/common'
import { AuthModule } from '@odpc-platform-x/nest-oidc-odpc-x-idp'

@Module({
  imports: [
    AuthModule.forRoot(
      {
        oidc: {
          issuer: process.env.OIDC_ISSUER!,
          clientId: process.env.OIDC_CLIENT_ID!,
          clientSecret: process.env.OIDC_CLIENT_SECRET!,
          redirectUri: process.env.OIDC_REDIRECT_URI!,
        },
        jwt: {
          privateKey: process.env.JWT_PRIVATE_KEY!,
          publicKey: process.env.JWT_PUBLIC_KEY!,
          issuer: 'my-app',
          audience: 'my-app',
        },
        appBaseUrl: process.env.APP_BASE_URL!,
      },
      MyAuthUserService, // or { provide: AUTH_USER_SERVICE, useFactory: ... }
    ),
  ],
})
export class AppModule {}
    # .env — Official ODPCX IdP (frontend: https://idp.odpcx.com)
OIDC_ISSUER=https://api.idp.odpcx.com
OIDC_CLIENT_ID=...
OIDC_CLIENT_SECRET=...
OIDC_REDIRECT_URI=https://your-app.example.com/v1/auth/callback

    Discovery document: https://api.idp.odpcx.com/.well-known/openid-configuration

    This wires up GET /auth/login, GET /auth/callback, POST /auth/logout, GET /auth/me, and exports AuthGuard for use on your own protected routes. Layer your own RolesGuard / @Roles() on top — that's intentionally not part of this package.

HTTP API

Routes

Method / PathBehavior
GET /auth/login Redirect (302) to ODPCX IdP authorization endpoint. Sets sx_oauth_tx cookie (httpOnly, sameSite=lax, maxAge=5min) containing PKCE state/nonce. Returns 503 JSON if IdP discovery fails.
GET /auth/callback
?code&state&error		 Success: verify tx cookie + state, exchange code for IdP tokens, call host's AuthUserService.onLogin(), sign session JWT, set sx_session cookie, redirect (302) to appBaseUrl. Error from IdP (?error=...): clear tx cookie, redirect to appBaseUrl. Invalid tx/state: return 401 JSON. onLogin throw: return 500 JSON.
GET /auth/me
(AuthGuard)		 Return JSON: SessionUser from the session cookie, or if host supplied AuthUserService.getMe(), return its result. Expired/absent session: 401.
POST /auth/logout
(AuthGuard)		 Clear sx_session cookie, return JSON { logoutUrl }. Client must navigate to logoutUrl itself (window.location = logoutUrl). Stale/expired cookie: 401.

Auth guards

Protecting your own routes

Apply AuthGuard to any route that needs authentication. The guard attaches the JWT payload to req.jwtPayload:

import { Controller, Get, Req, UseGuards } from '@nestjs/common'
import { AuthGuard } from '@odpc-platform-x/nest-oidc-odpc-x-idp'
import type { SessionUser } from '@odpc-platform-x/nest-oidc-odpc-x-idp'

@Controller('api')
export class MyController {
  @UseGuards(AuthGuard)
  @Get('my-data')
  myData(@Req() req: Request) {
    const user = (req as any).jwtPayload as SessionUser
    // user.sub, user.email, user.displayName, ...
    return { data: 'only for authenticated users' }
  }
}

Security

Session token notes

The session JWT payload contains sub, email, displayName (all from SessionUser) plus standard JWT claims (iss, aud, iat, exp). The JWT is signed with RS256 and stored in a cookie.

⚠️ WARNING: The IdP's idToken is embedded in the session cookie payload (for logout flow) but the cookie is signed, not encrypted — the payload is readable via base64 decode. Do not include secrets or sensitive data in SessionUser that the host's onLogin() method returns.

Session expiry: once a JWT expires (based on accessTtlSeconds), the cookie is no longer valid. The client must log in again via GET /auth/login — there is no refresh token flow. Design your UX so users hit login naturally, or add a client-side timer to redirect before expiry.

Advanced

Config loading

This package does not support forRootAsync — AuthModule.forRoot() accepts a plain options object. Load environment variables before calling forRoot:

import * as dotenv from 'dotenv'
dotenv.config()

AuthModule.forRoot(
  {
    oidc: {
      issuer: process.env.OIDC_ISSUER!,
      clientId: process.env.OIDC_CLIENT_ID!,
      clientSecret: process.env.OIDC_CLIENT_SECRET!,
      redirectUri: process.env.OIDC_REDIRECT_URI!,
    },
    jwt: {
      privateKey: process.env.JWT_PRIVATE_KEY!,
      publicKey: process.env.JWT_PUBLIC_KEY!,
      issuer: 'my-app',
      audience: 'my-app',
    },
    appBaseUrl: process.env.APP_BASE_URL!,
  },
  MyAuthUserService,
)

If you need dependency injection for config (e.g., loading from a ConfigService), wire the options in your module's setup: 

import { Module, Inject } from '@nestjs/common'
import { ConfigService } from '@nestjs/config'
import { AuthModule, AUTH_USER_SERVICE } from '@odpc-platform-x/nest-oidc-odpc-x-idp'

@Module({
  imports: [ConfigModule, AuthModule.forRoot(
    {
      oidc: {
        issuer: configService.get('OIDC_ISSUER'),
        clientId: configService.get('OIDC_CLIENT_ID'),
        clientSecret: configService.get('OIDC_CLIENT_SECRET'),
        redirectUri: configService.get('OIDC_REDIRECT_URI'),
      },
      jwt: {
        privateKey: configService.get('JWT_PRIVATE_KEY'),
        publicKey: configService.get('JWT_PUBLIC_KEY'),
        issuer: 'my-app',
        audience: 'my-app',
      },
      appBaseUrl: configService.get('APP_BASE_URL'),
    },
    { provide: AUTH_USER_SERVICE, useClass: MyAuthUserService },
  )],
})
export class AppModule {}

Public API

Everything exported from the package root (src/index.ts):

  • AuthModule — dynamic module, use via .forRoot(options, provider)
  • AUTH_USER_SERVICE — DI token for the host-supplied AuthUserService
  • AuthGuard — Nest guard, verifies the session cookie and attaches req.jwtPayload
  • DEFAULT_SESSION_COOKIE — the string 'sx_session'
  • BuildLoginUrlUseCase — exported for controller.disabled mode
  • HandleCallbackUseCase — exported for controller.disabled mode
  • GetMeUseCase — exported for controller.disabled mode
  • LogoutUseCase — exported for controller.disabled mode
  • AuthModuleOptions (type)
  • AuthUserService (type) — onLogin(claims): Promise<SessionUser>, optional getMe?(sessionUser): Promise<unknown>
  • OidcClaims (type) — sub, email, displayName, idToken, refreshToken?, pictureUrl?
  • SessionUser (type) — sub, email, displayName, plus any extra fields the host adds (e.g. roles)

Read before you rely on this

Caveats

  • controller.prefix is a no-op. Nest's @Controller() path is fixed at class-decoration time, so a per-instance dynamic prefix isn't cheap to support (see the // ponytail: comment in src/controller/auth.controller.ts). The controller is permanently mounted at /auth/*. Wrap it in your own RouterModule config if you need a different mount point.
  • controller.disabled omits the built-in AuthController entirely — the use-cases (BuildLoginUrlUseCase, HandleCallbackUseCase, GetMeUseCase, LogoutUseCase) and AuthGuard are still provided and exported, so you can write your own routes against them.
  • Lazy re-discovery. OIDC discovery against the IdP happens lazily inside the adapter, not only at boot — if the IdP is down when the app starts, the module still comes up; the next request that needs the IdP (login/callback) retries discovery and recovers automatically once the IdP is back, no app restart required.
  • No role/permission guards included. RolesGuard, @Roles(), any authorization beyond "is this a valid session" is a host concern — layer your own on top of AuthGuard.
